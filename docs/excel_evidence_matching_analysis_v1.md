# Excel Evidence Matching Analysis v1

## 목적과 범위

이 문서는 사용자가 제공한 엑셀 3개가 Smartstore / MakeShop / PlayAuto / Ably 수동매칭 축소 근거로 쓸 수 있는지 확인한 진단 메모다.

분석 대상 파일:

- `가격 수정 리스트 - 수정하였습니다.xlsx`
- `플레이오토 스스_옵션_변경양식.xlsx`
- `플레이오토 스스_일반_변경양식.xlsx`

이 분석은 DB 반영 단계가 아니다. 원본 `.xlsx`는 읽기 전용 증거 자료로만 사용하며, 원본 파일을 git에 추가하지 않는다.

## 파일/시트별 역할

### 가격 수정 리스트

이 파일은 판매처별 코드 연결 참고자료로 쓸 수 있다.

주요 시트별 역할:

- `셀피아`: 셀피아 상품코드/대표 상품코드와 각 판매처 블록이 한 행 또는 인접 행에 섞여 있어 cross-channel 증거로 사용 가능하다.
- `메이크샵`, `DB_1`: `자체 상품 코드`, `상품코드`, `상품명`, `옵션명`, `판매가`, `옵션가격`, `옵션조합가격` 확인 가능.
- `스마트스토어`, `DB_2`: `자체 상품 코드`, 스마트스토어 상품코드 후보, 상품명, multi-line 옵션명, 옵션별 펼침 열(`옵션명 `) 확인 가능.
- `플레이오토`, `DB_3`: `P-...` 자체 코드, `sellpia_...` 상품코드, 상품명, multi-line 옵션명, 옵션별 펼침 열(`옵션명 2`) 확인 가능.
- `에이블리`, `DB_4`: `A-...` 자체 코드, `sellpia_...` 상품코드, 상품명, multi-line 옵션명, 옵션별 펼침 열(`옵션명 2`) 확인 가능.
- `DB_0`: 한 행에 `상품코드`, `메이크샵`, `스마트스토어`, `플레이오토`, `에이블리`, `상품명`, `매입옵션명`, `옵션명`, 가격류가 있어 판매처 간 연결 근거로 가장 유용하다.

쓸 수 있는 컬럼:

- 셀피아 계열: `상품코드`, `대표 상품코드`
- 판매처 연결: `메이크샵`, `스마트스토어`, `플레이오토`, `에이블리`, `자체 상품 코드`, `상품코드`
- 보강 근거: `상품명`, `매입옵션명`, `옵션명`
- 가격 보조: `기존가격`, `수정가격`, `판매가`, `옵션가`, `옵션조합가격`

주의할 컬럼:

- 가격 컬럼은 같은 상품/옵션 증거가 아니라 보조 검산용이다. 가격만 같다고 자동매칭하지 않는다.
- `#NAME?`가 보이는 계산 컬럼은 원본 수식 해석 결과가 아니므로 매칭 근거로 쓰지 않는다.
- Smartstore `옵션명`은 한 셀에 여러 줄로 들어가며, 펼침 열과 줄 순서를 검증해야 한다.
- `DB_3`, `DB_4`에는 일부 대괄호가 닫히지 않은 옵션 텍스트 예시가 있어 own_sku 추출 실패/경고 대상으로 둔다.

확인된 표현 사례:

- own_sku: `골드/6mm바[GPA-7-113]`, `스틱[PI-7-05]`, `원타입[SA-3-06_5]`
- 색상 동의어 후보: `핑크골드`, `로즈골드`, `핑골`, `골드`, `옐로우골드`
- 위험 표현: `크리스탈`, `크리스탈AB`, `실버`, `주문제작`, `세트`, `한쌍`, `낱개`

### 플레이오토 스스_옵션_변경양식

`옵션기본`은 Smartstore 옵션 단위 매칭 근거로 가장 직접적이다.

주요 컬럼:

- `*쇼핑몰`
- `*계정`
- `*판매자관리코드`
- `온라인 상품명`
- `쇼핑몰상품코드`
- `옵션1 값`
- `옵션 SKU 코드`
- `배송처코드`
- `추가 금액`
- `판매가능재고`
- `*판매수량`
- `*옵션상태`

쓸 수 있는 컬럼:

- `*판매자관리코드`: `sellpia_11422` 형식이면 셀피아 상품코드 후보 `11422` 추출 가능.
- `옵션 SKU 코드`: `sellpia_11422-1` 형식이면 셀피아 SKU 후보 `11422-1` 추출 가능.
- `쇼핑몰상품코드`: Smartstore productNo 후보로 사용 가능.
- `옵션1 값`: Smartstore option text와 own_sku 후보 추출에 사용 가능.
- `온라인 상품명`: 같은 상품인지 보강 evidence로 사용 가능.

주의할 컬럼:

- `판매가능재고`, `*판매수량`, `추가 금액`은 옵션 매칭 보조 자료일 뿐 확정 근거가 아니다.
- `추천옵션-스마트스토어_w_ground`는 추천 옵션 값 구조를 알려주는 보조 시트이며 개별 SKU 매칭 근거로는 약하다.
- `세트`, `크리스탈`, `크리스탈AB`, `실버`가 함께 등장하므로 위험 토큰 플래그가 필요하다.

샘플:

- `*판매자관리코드=sellpia_11422`, `쇼핑몰상품코드=13458170628`, `옵션1 값=스틱[PI-7-05]`, `옵션 SKU 코드=sellpia_11422-1`
- `옵션1 값=싱글/크리스탈[PI-7-01]`, `옵션 SKU 코드=sellpia_11421-1`

### 플레이오토 스스_일반_변경양식

`쇼핑몰상품`은 상품 단위 구조와 multi-line 옵션/SKU 정렬을 확인하는 데 유용하다. `SKU상품`은 셀피아 SKU별 속성/배송처 코드 사전으로 유용하다.

주요 컬럼:

- `쇼핑몰상품`: `판매자관리코드`, `온라인 상품명`, `쇼핑몰 상품번호`, `옵션`, `SKU`, `배송처코드`, `옵션 추가금액`, `옵션 판매수량`
- `SKU상품`: `SKU코드`, `SKU명`, `속성`, `배송처코드`
- 보조 시트: `쇼핑몰(ID)`, `템플릿`, `카테고리`

쓸 수 있는 컬럼:

- `판매자관리코드`: `sellpia_11422` 형식의 셀피아 상품코드 후보.
- `쇼핑몰 상품번호`: Smartstore productNo 후보.
- `옵션`: multi-line 옵션 텍스트와 own_sku 후보.
- `SKU`: multi-line `sellpia_상품코드-옵션번호` 후보.
- `SKU상품.SKU코드`: 셀피아 SKU 후보.
- `SKU상품.속성`: 옵션명과 own_sku 후보.
- `배송처코드`: 같은 상품군/출처 보조 근거.

주의할 컬럼:

- `쇼핑몰상품.옵션`과 `쇼핑몰상품.SKU`는 줄 순서가 맞을 때만 1:1 매칭 가능하다.
- 이번 샘플 301개 상품행에서는 옵션 줄 수와 SKU 줄 수 불일치가 확인되지 않았지만, 향후 stage에서는 반드시 row-level precheck가 필요하다.
- `[no ball 옵션 설명 참고]` 같은 안내 줄은 옵션값이 아니라 메모로 분리해야 한다.
- `14K`, `써지컬`, `925실버`는 색상이 아니라 소재/재질 속성으로 분리해야 한다.

샘플:

- `옵션=[옵션] / 스틱[PI-7-05] / 하트[PI-7-06] ...`
- `SKU=sellpia_11422-1 / sellpia_11422-2 ...`
- `SKU상품`: `SKU코드=sellpia_10000-1`, `속성=별[PM-7-01]`

## 추출 규칙

### 셀피아 SKU 추출

- `sellpia_11422-1` -> `11422-1`
- `sellpia_11422` -> 상품 단위 후보 `11422`
- `가격 수정 리스트.DB_0.상품코드`의 `10529-1`은 바로 셀피아 SKU 후보로 본다.
- `가격 수정 리스트.셀피아.대표 상품코드`의 `10529`는 셀피아 상품코드 후보로 본다.
- DB 비교 시 `product_code.code_alias.code_system='selfpia_sku'`와 비교 가능한 정규형은 `숫자-옵션번호`다.
- 상품 단위만 있는 `sellpia_11422`는 옵션 SKU 확정에 쓰지 않고 같은 상품 후보를 좁히는 데만 쓴다.

### own_sku 추출

- 옵션명/속성의 대괄호 내부 코드를 후보로 추출한다.
- 예: `골드/6mm바[GPA-7-113]` -> `GPA-7-113`
- 예: `스틱[PI-7-05]` -> `PI-7-05`
- 예: `원타입[SA-3-06_5]` -> `SA-3-06_5`
- 닫는 대괄호가 없거나 bracket 안에 설명 문구가 섞이면 `parse_warning`으로 두고 자동확정 금지.
- DB 비교 시 `product_code.code_alias.code_system='own_sku'`와 비교한다.

### Smartstore productNo 후보 추출

- `플레이오토 스스_옵션_변경양식.옵션기본.쇼핑몰상품코드`를 Smartstore productNo 후보로 본다.
- `플레이오토 스스_일반_변경양식.쇼핑몰상품.쇼핑몰 상품번호`를 Smartstore productNo 후보로 본다.
- `가격 수정 리스트.스마트스토어/DB_2.상품코드`가 숫자형 productNo로 반복되는 경우 Smartstore productNo 후보로 본다.
- 같은 `selfpia_sku`가 여러 productNo로 갈라지면 자동확정 금지.

## 상품명 보강 규칙

상품명은 단독 확정 근거가 아니다. 다음 정규화 후 충돌 여부만 확인한다.

- 공백 제거
- 대소문자 통일
- 특수문자 제거
- 반복 공백 정리
- 괄호 문구, 주문제작 문구, `[5개]` 같은 수량 문구는 제거 후보로 진단하되 자동 제거 규칙은 별도 검증 후 적용

상품명 정규화 결과가 서로 충돌하면 수동검수로 보낸다.

## 옵션명 정규화 연결 규칙

이미 커밋된 옵션명 정규화 사전과 연결하는 방향으로 둔다.

- `핑크골드` = `로즈골드` = `핑골` = `rose gold` = `RG`
- `옐로우골드` = `골드` = `yellow gold` = `YG`
- `크리스탈`과 `크리스탈AB`는 자동 동일 처리하지 않는다.
- `AB`는 token 단위로만 매칭한다.
- `화이트골드`와 `실버`는 자동 동일 처리하지 않는다.
- `14K`, `써지컬`, `925실버`는 색상이 아니라 소재로 분리한다.
- `주문제작`, 바 길이, `한쌍`, `낱개`, `세트`, 수량 표현은 별도 속성 분리 후보로만 진단한다.

추가 검토할 표현:

- `핑골`
- `주문제작`
- `[no ball 옵션 설명 참고]`
- `원타입`
- `5개`, `세트`, `한쌍`, `낱개`

## auto-confirm-ready 후보 조건

아래 조건을 모두 만족해야 한다.

- 셀피아 SKU가 1개로 추출됨.
- own_sku가 있으면 DB own_sku와 일치함.
- Smartstore productNo 후보가 1개임.
- 상품명 정규화 비교에서 충돌 없음.
- 옵션명 정규화 후 1:1 매칭됨.
- 같은 selfpia_sku가 여러 Smartstore productNo로 갈라지지 않음.
- 같은 Smartstore productNo + option text 조합이 여러 selfpia_sku와 충돌하지 않음.
- multi-line 옵션/SKU 줄 수가 일치함.
- `크리스탈`/`크리스탈AB` 위험 오매칭 없음.
- `화이트골드`/`실버` 위험 오매칭 없음.
- `세트`/`한쌍`/`낱개`/수량 표현 충돌 없음.
- 가격만 같은 것이 아니라 코드/옵션 근거가 있음.

## manual_review_required 조건

아래 조건은 수동검수로 남긴다.

- selfpia_sku 추출 불가.
- own_sku 추출 불가 또는 DB 불일치.
- 같은 자사코드가 여러 상품 후보와 연결.
- 상품명 충돌.
- 옵션명 정규화 후 여러 후보.
- 옵션 수 불일치.
- multi-line 옵션/SKU 줄 수 불일치.
- `크리스탈`/`크리스탈AB` 혼동 가능.
- `AB` 오탐 가능.
- `화이트골드`/`실버` 혼동 가능.
- `세트`/`한쌍`/`낱개` 충돌.
- 가격만 같고 코드/옵션 근거 부족.

## 결론

세 엑셀은 수동매칭을 줄이는 근거로 쓸 수 있다. 특히 PlayAuto Smartstore 옵션 양식은 `옵션 SKU 코드`와 `쇼핑몰상품코드`, `옵션1 값`이 한 행에 있어 Smartstore option-level 후보 생성에 강하다. 다만 자동확정은 셀피아 SKU, own_sku, productNo, 상품명 보강, 옵션명 정규화, multi-line alignment, 위험 토큰 검사를 모두 통과한 행으로 제한해야 한다.
